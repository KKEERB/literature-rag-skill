# 知识切分与组织

核对日期：2026-10-26。这里的 chunk 是可检索的结构化知识条目。当前切分主要由模型在读全文时完成，程序负责验证、投影与索引；不是程序按固定 token 长度切全文。

## 1. 两种生产路径不能混为一种格式

| 方面 | 快速入库 | 完整精读 |
| --- | --- | --- |
| 内容载体 | 紧凑 `items`，发布包标记 `fast_pdf_pack_v1` | `02_machine_evidence_pack.json` 中的结构化知识对象 |
| 条目类别 | `claim`、`method`、`limitation`、`figure`、`definition` | 核心论点、方法、图、限制、项目关系、外部背景等有显式 `chunk_id` 的对象；争议对象存在兼容处理 |
| 形成方式 | 第一轮写条目，第二轮逐条判定；只原样选择通过项 | 完整精读知识模型中的对象经确定性渲染和归一化进入索引 |
| 身份 | `pdf:<源PDF哈希>:<条目ID>` | 原模型已有的稳定 `chunk_id`，保留文献与对象身份 |
| 检索别名与关联 | 紧凑 schema 不强制专门的检索问句或关联字段，可能为空 | 支持中英文检索问句、`related_chunk_ids` 和类型化对象引用 |

两条路径最终映射到统一索引字段，但生产细节与信息密度不同。不能用完整精读字段的丰富程度推定所有快速条目都具备同样上下文。

## 2. 一个条目应保留什么

下表是对现有字段作用的说明，不是新增 schema；不同生产路径的必填程度不同。

| 信息 | 字段示意 | 对理解和引用的作用 |
| --- | --- | --- |
| 文献与对象身份 | `source_id`、`chunk_id`、`item_id`、PDF/模型哈希 | 区分来源、条目与版本；防止把不同论文的同号对象混用 |
| 断言 | `text_zh`、可选 `text`、`kind` | 保存知识陈述及类别；中文陈述可能是模型重述，不等于逐字译文 |
| 来源与认识论身份 | `source_kind`、`epistemic_status` | 区分论文观察、作者解释、项目推断和外部材料 |
| 原文定位 | `evidence` 中的页码、短段、章节、图表等 | 回到具体原文；PDF 页号与印刷页码需分清 |
| 质量状态 | `verification_status`、`support_level`、质量台账 | 表达记录的检查和支持范围，不能当成校准后的正确概率 |
| 使用范围 | `usable_for`、`cannot_support` | 明确可回答什么，以及不能升级为什么结论 |
| 查询与联系 | 中英文 `retrieval_queries`、`related_chunk_ids` | 辅助检索或保留关联；有字段不等于实现了关系检索 |
| 人工与版本状态 | 审阅事件、当前判断、替代关系 | 知识文本之外单独保存，查询时附加 |

条件、数值、单位、时间窗口、对象和否定通常写在断言与证据中，**目前不是所有条目都有结构化的条件槽位**。schema 的字符串非空检查不能证明条件齐全。这是独立复核需要检查的内容，也是可讨论的设计选择。

当前没有统一的固定 chunk 长度、滑动重叠或“一句一个 chunk”硬规则；“原子性”依赖生产者切分与复核者判断。代码能校验一项对应一个复核决定，但不能机械证明该项只含一个完整、可独立判断的断言。

## 3. 上下文保留到什么程度

索引的 `context` 通常是“某论文的核心论点/方法/图表证据”等标题与类别说明，不是完整相邻段落。原文短段在证据字段里保留，全文逐页提取缓存也保留，但主论文检索路径不会把整个原 PDF 自动切成原文 chunk 并全部召回。

因此存在两个不同问题：

- 已入库条目是否忠实：回读其原文、条件与相关图文可检查。
- 重要内容是否根本没有入库：仅检索已有条目不能发现，需要独立覆盖清单、原文检查或另行评估。

跨页定义、公式变量、方法假设和结果之间的关系可能超过单个条目。当前关联 ID 保留联系，但不能假定查询时自动连同这些上下文一起返回。是否加入原文段落层、父子层次或条件化上下文扩展，属于待验证改进。

## 4. 图表的特殊处理

**当前完整精读实现**：图对象保存原图注、中文图注、直接观察、作者解释与不能推出的结论等内容。归一化入索引时，`text` 取原图注，`text_zh` 将中文图注、直接观察和作者解释连接起来，认识论身份统一设为 `author_interpretation`。图被实际标为 `visually_reviewed` 时支持层为 `direct`，否则为 `indirect`；其他质量门仍独立生效。

这保留了丰富图文信息，但也将不同性质的陈述合在同一检索单元中。审核应具体检查：命中作者解释时，是否会让直接观察看起来已经证明该解释；连接后的文本是否丢失字段语境；图内数值和图文矛盾如何保留。

**当前快速实现**：图项按通用条目映射为 `figure_evidence`，不套用上述完整图对象的图注合并逻辑。发布通过项时统一赋予 `direct` 与 `anchored` 等索引标签，但仅凭 `kind=figure` 不能获得“实际看图”的证明。基于图像的断言另需绑定实际页面渲染检查记录。

同一标签在不同生产路径中的形成方式不完全相同。它们是工作流状态，不是通用证据强度标尺；这也是应交给审核者评价的实现不对称。

## 5. 权限层次与派生材料

论文内容中的项目迁移、`codex_inference`、项目或外部来源，及明确的 context-only 来源，进入低权限背景层。论文外部引用不能因出现在同一 evidence pack 中就成为该论文直接结果。

RAG Markdown 从结构化模型渲染，并校验 chunk ID 对应关系；主论文索引不是再对 Markdown 随机切片。全文翻译与 Reader Note 中的叙述不作为第二套独立证据重复索引。历史修订对象可保存在生成记录中，遍历时排除 `generation` 下的历史副本，避免把审计历史当成新证据。

工作记忆用于背景和查询提示，固定为 `context_only`。个人读后感、模型给出的理解反馈和参考答案不会自动升为科研条目。

## 6. 应由审核者检查的取舍

| 当前选择 | 可能收益 | 待验证代价 |
| --- | --- | --- |
| 模型生成结构化条目 | 查询结果接近研究问题，易附条件与边界 | 生产时遗漏或解释偏差可能在所有后续检索中持续存在 |
| 不用固定长度硬切 | 避免机械截断一句条件或一段论证 | 粒度依赖模型，复合陈述和过长图项可能不一致 |
| 原文锚点与文本分开存 | 可追溯并减少冗余 | 检索正文未必包含需要的定义或限定上下文 |
| 图解释合并检索 | 一次获得图注、观察和解释 | 混合认识论身份，难单独评价每个子断言 |
| 规范模型生成派生产物 | 减少人工复制产生的漂移 | 共用的错误可能一致地传到所有派生产物 |

不要只问“用多大 chunk”；先问每个典型科研问题需要哪种证据单元，再用真实后续实验比较召回、上下文充分性和引用忠实性。
