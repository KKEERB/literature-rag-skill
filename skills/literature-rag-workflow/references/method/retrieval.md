# 检索、排序与回答

核对日期：2026-10-26。本节描述参考实现的主检索路径；数值是实现快照，不是推荐的最优参数。便携运行文件随候选提供，但不包含现成知识库。

## 1. 索引里实际查什么

主数据表为 `sources` 和 `chunks`，全文检索表为 SQLite FTS5 `chunks_fts`。chunk 保存证据与状态，FTS 表保存用于召回的字段：

| FTS 字段 | 当前内容 |
| --- | --- |
| `chunk_id` | 用于关联记录，本身不参与 FTS 分词索引 |
| `title` | 来源标题 |
| `body` | `text_zh`、`text`、简短 `context`、`cannot_support` 连接而成 |
| `aliases` | DOI、条目 ID、中英文检索问句和来源标签 |
| `ngrams` | 标题、正文与别名中的中文相邻二字组合 |

原文证据短段虽然保存在 `evidence` 中，但不作为独立字段加入上述 FTS 正文；若生产者把相同文字写入 `text`，那部分可以被检索。主路径没有对原文缓存作第二次全文召回。人工意见在检索后附加，当前 FTS 正文也不自动索引这些意见。

**待检验问题**：把 `cannot_support` 放入正文可能帮助找出限制，也可能让否定一个机制的条目因包含机制词而命中。命中只说明文本相关，不能直接当成支持。仅检索人工意见里的词也不保证找到被批评条目。

## 2. 查询与候选生成

1. 查询做 Unicode NFKC 归一化并转小写；提取英文/数字词项与中文二元组，保序去重。例：`极光机制` → `极光`、`光机`、`机制`，不是词典语义分词。
2. 取前 32 个词项，逐个加引号后用 `OR` 连接为 FTS 查询。该限制是召回阶段参数，不是知识 chunk 的长度。
3. 用 FTS5 BM25 排序取得至多 250 个非 tombstone 候选；字段权重按 `chunk_id/title/body/aliases/ngrams` 为 `0/5/2/3/1.5`。
4. 另外查询 chunk ID、DOI 的大小写不敏感精确匹配，以及标题包含匹配，至多 250 个；此路径没有显式 `ORDER BY`。
5. 先放身份/标题候选，再放 BM25 候选，按 chunk ID 去重。随后解析明确修订的替代候选并附加审阅记录，再计算最终规则分数。

数值 BM25 负责其中一条候选列表的顺序，**最终排序不直接把 BM25 数值代入加权总分**。精确路径置前、候选顺序和修订候选处理均可能影响最终位置。

当前未实现 embedding 召回或语义重排；同义表达的恢复依赖词项重合、双语内容和预先写入的检索问句。英文问句与中文问句都进入 aliases，但后述“精确问句加分”仅检查中文问句列表，这是当前实现的不对称。

## 3. 当前规则排序

对准备评分的候选列表，以其序号 `i` 开始，基础分为 `max(1, 100 − 0.75 × i)`，再加入下表规则；最终按分数降序、chunk ID 确定相同分数顺序。

| 条件 | 当前加分/减分 |
| --- | --- |
| 归一化查询等于 DOI、chunk ID 或完整题名 | +140 |
| 不满足上条，但查询是题名子串 | +70 |
| 查询等于条目正文或预先写入的中文检索问句 | +140 |
| 来源类型 | 论文证据 +55；已提升外部来源 +28；任务文档 +16；外部综述 +12；raw source +2 |
| 验证状态 | `anchored` +28；`externally_verified` +16；待人工检查 +0 |
| 支持层 | `direct` +10；`indirect` +4；`speculative` −8 |
| 权限或认识论身份 | `context_only` −45；项目应用或模型推断另 −25 |
| 指定 domain 字符串出现在 project profile 中 | +8，是提示，不是过滤 |

任务工程文档另有定向加分：查询包含完整归一化题名，或满足长度/形式条件的文档标识符命中来源身份时，可加 180；有工程查询词且与别名至少三个词项重合时使用 `min(165, 90 + 12 × 重合数)`。这些规则属于现有领域适配，不宜照搬为通用科学库权重。

得分混合了词面相关性、来源类型和工作流质量状态，不是相关概率或事实正确率。低分背景可能很相关，高分论文条目也可能答非所问；应通过问题集评估这种混合是否合适。

## 4. 去重、版本与关联

- 默认排除隔离内容与明确被替代条目。去重依据论文身份、类别、文本、认识论身份、证据锚点、人工状态及引用限定；不同异议不能被合并吞掉。
- 同 DOI、同一个 `C001` 或相同题名，不足以判定两条陈述相同。按论文身份计数也不代表实验独立。
- 优先版本来自显式且仍与输入绑定的修订关系，不从“日期更新”自动推出。旧条目只在明确对应的替代关系中被替代。
- DOI/完整标题查询可把同一论文中可引用的明确优先版本放前；这不改变其他论文已经占据的位置。
- `related_chunk_ids` 已保存，但当前主检索不沿它自动递归召回相邻方法、条件或图条目。已有依赖台账可在 top-k 后附加经审核的来源依赖（例如共享模拟运行），这是提示已有关系，不是图检索或独立性证明。

最终默认返回 top-k=10。工作记忆使用独立 FTS 检索，最多返回五项背景、前三项的文本作为 `query_expansions` 提示；这个返回字段不会在本函数内自动触发第二轮查询。

## 5. 能检索到与能支撑回答分别判断

符合引用条件需要综合：来源与条目权限、验证状态、可用定位、当前质量台账、源文件有效性、版本和有效的人审事件绑定。仅 `anchored`、高排序分或 `faithful` 都不单独构成充分条件。

| 情况 | `supports_claim` | `citation_allowed` / 模式 | 回答要求 |
| --- | --- | --- | --- |
| 来源与机器门通过，未人工审阅或已接受 | 可为 true | 可为 true / `standard` | 保留来源、条件、覆盖缺口和真实人审状态，不称为独立证实 |
| 来源与机器门通过，但人工不接受/未决 | false | 可为 true / `with_human_dissent` | 只能同时说明论文表述与异议；不能写成无争议结论 |
| 来源、质量、版本或审阅事件绑定失败 | false | false / `blocked` | 不直接引用；说明缺口并回到相应原文/绑定检查 |
| 仅背景材料或项目推断 | false | 不满足主证据引用门 | 用于背景、提问或待验证假设，不能独立支撑科学结论 |

`citation_allowed` 表示在系统规则下允许该种引用，不是“该断言为真”。争议条目的 `answer_text` 在原条目文本后附加 `citation_qualification`，保留用户意见；未附意见时如实写未附意见，不能生成一个理由。

系统查询返回证据与限定，不会单靠 SQLite 生成完整科研答案。最终模型仍需判断问题相关性、连同必要上下文回读原文并综合回答。回读要求不等于每一次 query 已自动完成原文语义复核。

## 6. 候选改进如何提出

可以比较原文层/知识层双路检索、混合召回、重排、父子上下文、条件字段、观察与解释分项、关联扩展等，但逐项明确它解决哪种失效。每次比较先固定同一来源集和查询集，改变一项机制；同时报告检索、上下文、回答忠实性、延迟与可测成本，不只选一个有利指标。

核对入口：`knowledge_system_core` 中的 `insert_source_and_chunks`、`lexical_terms`、`fts_match_query`、`search_database`、`score_chunk`、`mission_document_query_boost`、`evidence_result`，以及 `knowledge_dependencies.annotate_dependencies`。原文和实际状态始终优先于此日期快照。
