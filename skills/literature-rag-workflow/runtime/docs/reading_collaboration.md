# 两轮入库、精选精读与条目审阅

## 工作流与证据层

默认先处理用户明确提供或选定的 PDF：第一轮读取原文并生成结构化条目，第二轮以独立任务再次读取原文、复核来源和陈述。只有满足机器来源及复核门的条目进入本地 RAG；机器通过不表示人工已读或科学结论已证实。缺失、未核验和隔离项目保留原因，不得写成通过。已处理条目可以检索，人工精读由用户另行选择。

用户选择精读后，先检查原 PDF 与现有材料的版本及哈希绑定，再复用或按现有生成流程补充 Reader Note 和调研卡。`literature_learning.py select` 只创建会话和工作单；它不表示精读材料、独立复核或人工阅读已经完成。使用 `reading_sessions.py register-materials` 绑定实际产物；登记不代替内容及视觉验收。

原 PDF 是证据源，结构化条目和 Reader Note 均为派生产物。论文报告、作者解释、外部证据和个人／项目推断分层保存；准确引用、数字、公式和关键论点必须回查原文。本流程不生成全文翻译。

## 默认清单与人的真实判断

用户说“我读完了”或要求审核时，展示当前版本的重点论点清单，不以答题或 `reading_ready` 为前置条件。默认最多十条；只从实际入库条目选择，保留原论点、页码、图表定位和审阅状态，排除重复、个人假设及项目推断。优先选择关键图解释、图中证据与文字结论的对应、作者的机制推断及其条件边界；纯事实、数字及仪器归属通常两条、最多三条。解释类不足时如实少列，不用事实题凑数。

清单一经展示，其内容、编号与输入版本保持固定。用户可以批量回答“接受／不接受”，意见可选。只记录明确指出的编号；不推断未回答项，也不把模型建议当作人的意见。接受仅表示该条忠实于论文，不代表整篇论文或其机制已获证实。只有用户主动要求时才进入深入问答；学习反馈与科研条目审阅分开。

运行前设置 `LITERATURE_RAG_HOME` 为用户自己的工作区，并使用已配置的 Python 和绝对路径；以下命令仅示意入口，实际参数以对应 `--help` 为准：

```text
python scripts/review_checklists.py generate --database <用户数据库> --source-id <来源ID> --output <会话目录>
python scripts/review_checklists.py show --session <会话目录>
python scripts/review_checklists.py present --session <会话目录> --message-ref <实际展示消息引用>
python scripts/review_checklists.py submit --session <会话目录> --input <真实用户回复JSON> --confirmed
```

`present` 只能在清单完整实际展示后记录，并返回用于绑定回复的展示事件。提交输入必须包含 `checklist_id`、`presentation_event_id`、`actor=user`、真实 `user_message_ref` 和原样 `human_statement`。复杂回复可忠实转换为 `decisions`，每项使用清单编号、`faithful`、`needs_revision` 或 `unresolved` 及可选意见。歧义需澄清，不能默认全接受。`--confirmed` 表示执行用户已经实际授权的判断；它不创造人工判断。

审阅绑定对应版本；过期清单不得写入当前版本。旧记录与意见保留，新版本不能自动继承旧认可。发布后的清单或阶段检查若失败，应单独报告并补做，不将失败隐藏成成功。

## 检索、异议与修订

接受、未回答、不接受和未决分别保留。机器和来源允许引用有异议的条目时，回答必须同时呈现论文原意、适用条件和用户异议；没有附意见就说明未附意见，不自行编理由。使用返回的 `answer_text`、`citation_qualification` 和 `citation_mode`；不能仅摘 `text` 丢失限制。`citation_mode=blocked`、来源损坏、机器复核失败、隔离和被替代的旧版本继续阻断，人工判断不能绕过这些条件。条目级审阅不能替代来源级历史声明，反之亦然。

有具体修改意见时，回查原文并提出确切差异；实际确认与独立复核后才进行版本化发布。阅读材料可能受修订影响，条目更新不等于 Reader Note 已更新。

## 阶段与抽样检查

核对原 PDF 来源、结构化条目、索引、实际检索与引用之间的身份和版本关系。按受影响范围分别报告机械检查、语义检查、检索和固定基准；只读已有基准，缺失标 `not_run`，不自动刷新。原文语义检查应实际读取对应页面和上下文，区分完整论点、条件、数字单位、归属、结论强度和定位；未检查或不能判断的项目不得标通过。

在需要时使用 `literature_cross_validation.py prepare` 产生计划与待审项，读取 `plan.json` 和 `semantic-task.json` 指定的原文后再用 `complete` 登记实际检查。报告保存在独立目录，不自动更改原 PDF、科学条目或活动库。抽样通过不等于全库科学正确；定时检查只有用户明确要求时另行配置。
